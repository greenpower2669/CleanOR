❓ Comment utiliser CleanOR

1. Collez votre texte dans la zone source. 2. Cliquez sur « Convertir ». 3. Cliquez sur « Copier le résultat ». Le bouton central ⇄ inverse le sens et reprend le résultat comme nouvelle entrée.

Le profil « outil opérateur réseau » reprend exactement la conversion de v0.1.2 : les retours et séparateurs d'espacement deviennent des espaces classiques (U+0020), sur une seule ligne. Le diagnostic ci-dessous permet de lire les codes Unicode présents dans le texte original, avant nettoyage. Le profil « CRM » conserve les retours à la ligne classiques. Le mode prudent remplace les caractères non représentables par « ? » ; le mode renforcé les retire. Si le système distant refuse encore le texte, ajoutez le symbole concerné dans ⚙️ Réglages.

🔎 Diagnostic des codes invisibles : voulez-vous afficher le texte original avec ses caractères invisibles dans un panneau interne ? Aucun nouveau pop-up du navigateur n'est ouvert.

Rapport technique sans contenu métier : seuls les codes, leurs fréquences et leurs positions Unicode sont copiés ; aucun mot du texte n'est inclus.

Contrôle SpanPersoOr : le motif Unicode présent dans le fichier fourni accepte lettres, nombres, ponctuations, séparateurs, symboles et marques. Les contrôles et caractères de formatage sont refusés. Les zones de commentaires génériques utilisent 2 047 unités UTF-16 ; la référence du demandeur a une limite de 150 et des caractères interdits supplémentaires. Le nettoyage peut normaliser des séparateurs acceptés par le motif pour éviter un collage problématique. La validation JavaScript ne garantit jamais la validation du serveur SGE.

Réglages : vos règles sont enregistrées dans le navigateur lorsque son stockage local est autorisé. Le fichier JSON s’importe ou s’exporte manuellement pour transférer vos règles. Aucun fichier voisin n’est recherché au démarrage.

Important : CleanOR ne connaît pas les validations internes de votre logiciel. Aucun nettoyage ne garantit l'acceptation par un serveur. Un collage de texte n'a pas de « format ANSI » imposable : l'encodage binaire n'existe que pour les fichiers importés/exportés. Une conversion avec pertes n'est pas réversible.

Vérifiez le texte avant l'enregistrement dans l'outil cible. Ne chargez pas de données professionnelles sensibles dans un dépôt GitHub public : les règles JSON ne doivent contenir que des exemples génériques.
